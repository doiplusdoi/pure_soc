# ADR-008: Evidence Storage Metadata And Export Model

Status: accepted
Date: 2026-04-28

## Context

Evidence is central to PureSOC. The product must store provider snapshots, uploads, generated reports, signed documents, checklist completions, action snapshots, audit exports, regulatory source snapshots, country registration drafts, and incident reporting drafts. Evidence must be tenant-scoped, traceable, exportable, and access-audited.

## Decision

Store evidence binaries in object storage and evidence metadata in PostgreSQL.

- The default local object storage is S3-compatible storage from the Compose catalog.
- Evidence metadata includes organization, control, jurisdiction, source type, source provider, title, description, storage URI, SHA-256 hash, MIME type, creator, timestamps, validity dates, linked assessment/action/source IDs, and export grouping.
- Downloads and exports require authorization and write an evidence access audit entry.
- Evidence can link to controls, jurisdictions, provider sync runs, regulatory sources, checklist runs, action runs, reports, and notification drafts.
- Upload scanning is modeled as a hook/interface so ClamAV or another scanner can be used without changing evidence contracts.
- Evidence and reports must not be made public by URL alone.

## Consequences

- Evidence packages can be generated by joining metadata, links, source references, and stored artifacts.
- Auditors can receive read-only access scoped to allowed organization data.
- Hashes and access logs support integrity and accountability.
- Implementation must handle storage adapter failures, scan status, expiration, and export authorization explicitly.
