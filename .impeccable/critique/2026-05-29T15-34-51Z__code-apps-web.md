## Anti-Patterns Verdict

This does not show the classic AI slop tells: no gradient text, no glassmorphism, no decorative dark glows, no hero-metric landing-page pattern. The product register is correct: restrained OKLCH tokens, system font, semantic HTML, and predictable controls.

The weaker tell is different: it reads like a contract harness promoted into product UI. Repeated panels, pills, tables, and source chips dominate the experience. A skilled compliance operator would trust the seriousness of the data model, but would pause at raw IDs, source query strings, and equally prominent implementation metadata.

Deterministic source scan: `npx impeccable detect --json --fast code/apps/web/src` returned `[]`. The live overlay command is not exposed by the installed CLI, so browser overlays were unavailable.

Manual source review found one absolute-ban pattern the detector missed: `.ps-fact` uses `border-left: 3px solid var(--ps-color-border)` in `code/packages/ui/src/index.ts`. It is not visible in the empty approval queue, but the token exists and should be replaced.

## Overall Impression

The product has a credible operational skeleton. It is accessible enough to inspect, traceable enough to audit, and consistent enough not to feel broken. The biggest opportunity is progressive disclosure: separate customer task flow from audit/source/debug detail.

## What's Working

- The design system is serious and restrained. OKLCH tokens, system typography, 8px max radii, and non-decorative color are appropriate for a compliance console.
- Status visibility is better than average. The UI surfaces saved state, fallback state, provider-write disablement, dashboard readiness, and source caveats.
- The local product path is honest. It avoids certification claims, direct DNSC submission, and provider write promises.

## Priority Issues

### [P1] The Romania onboarding page has too much simultaneous work

Why it matters: on mobile it measured about 8,543px tall with 21 fields, 9 visible actions, 6 sections, 12 panels, 3 tables, 50 status pills, and 14 source chips. Users must scan forms, source evidence, unsupported states, draft metadata, contract steps, and source maps at once.

Fix: convert it into a task flow: `Business details`, `Scope and services`, `Classification`, `Draft`, `Evidence and exports`, `Audit details`. Keep only the current step expanded. Move contract steps, source map samples, and notification metadata behind `Audit details`.

Suggested command: `$impeccable onboard`

### [P1] Traceability metadata is competing with product meaning

Why it matters: dashboard and workspace pages expose IDs and implementation strings such as organization UUIDs, `dashboard_snapshots`, `provider_connections:none`, `GET /organizations/:orgId/dashboards/snapshots/latest`, and source map IDs. This makes the UI feel internal and forces users to separate product state from engineering state.

Fix: show human labels by default. Move raw IDs and query strings into a collapsible `Traceability` drawer or per-row details disclosure.

Suggested command: `$impeccable distill`

### [P1] Primary actions are not prioritized

Why it matters: Romania outputs show `Run classification`, `Generate draft`, `Evaluate readiness`, `Readiness export`, `Draft export`, `Record checkpoint`, and `Attach evidence` together. Several are primary-colored, some are disabled, and the prerequisite chain is not obvious.

Fix: make one next action primary based on state. After no saved progress: only `Save progress`. After save: `Run classification`. After classification: `Generate draft` and `Evaluate readiness`. Exports appear only after their data exists. Disabled actions should explain the missing prerequisite.

Suggested command: `$impeccable clarify`

### [P2] Form guidance assumes domain knowledge

Why it matters: `CUI`, `Main NACE code`, `Romania service code`, and `Network and information systems` are real domain inputs, but the UI provides no examples, validation affordance, or source-mapped options. The service code in particular should not be free text if it drives classification.

Fix: add inline examples and switch service code to a searchable/selectable source-mapped option list. Add short helper text under NACE and CUI, not a separate help page.

Suggested command: `$impeccable clarify`

### [P2] Mobile is technically responsive but not ergonomic

Why it matters: no horizontal overflow is good, but the important pages become very long scrolls. Checkbox inputs render as 13px targets, command buttons are about 36px high, and primary actions sit mid-page rather than near the current task.

Fix: increase mobile target sizes to at least 44px, make checkbox rows larger, keep the current step action sticky at the bottom of mobile, and collapse audit tables by default.

Suggested command: `$impeccable adapt`

## Cognitive Load

Failure count: 6 of 8, high.

Failures: single focus, chunking, visual hierarchy, one thing at a time, minimal choices, progressive disclosure. Grouping is present but overused. Working memory is strained by domain codes and source terminology.

## Persona Red Flags

Alex, power user: no compact mode, no shortcuts, no batch operations, and source chips slow scanning across the dashboard.

Jordan, first-timer: unclear field meanings for CUI, NACE, and Romania service code. The first Romania page shows many sections before explaining the path.

Sam, accessibility-dependent user: semantic labels and skip links are good, but the Romania route starts at `h2` with no `h1`, disabled actions lack explanatory text, and mobile/touch targets are too small.

Casey, distracted mobile user: Romania onboarding is an 8,500px scroll with text-heavy tables and no sticky current action. Progress can be lost mentally even if the server keeps data.

## Minor Observations

- Title case varies: `Register Local Account`, `Select A Workspace`, `Create Workspace`, and sentence-case body copy feel slightly inconsistent.
- Dashboard empty state is clearer than the full dashboard. It has one action and low noise.
- The auth pages are clean, but `API session` and `local auth` pills feel more like test harness labels than customer-facing trust signals.
- Tables are useful for audit review, but not for the primary onboarding workflow.
